## 1. 파이썬이란

### 만든 사람과 역사

- 네덜란드 개발자 귀도 반 로섬(Guido van Rossum)이 만들었다.
- 1989년 12월, 네덜란드 CWI(Centrum Wiskunde & Informatica)에서 연말 휴가 중 구현을 시작했다.
- 1991년 2월에 첫 버전(0.9.0)을 공개했다. 이후 1.0(1994), 2.0(2000), 3.0(2008)
- ABC라는 언어의 후속으로 만들었고, ABC에서 가독성과 들여쓰기 아이디어를 가져왔다.
- 이름은 뱀이 아니라 영국 코미디 쇼 Monty Python's Flying Circus에서 따왔다.

### 특징과 장점

- **보일러플레이트가 적다.**
  - 클래스나 main 함수 같은 형식용 코드 없이 `print("Hello")` 한 줄로도 프로그램이 되어서, 하려는 일에 바로 집중할 수 있다.
- **필요한 도구가 이미 만들어져 있다.** 표준 라이브러리와 방대한 외부 라이브러리를 가져다 쓴다.
  - 파일 읽기나 날짜 계산 같은 기본 기능은 표준 라이브러리에, 데이터 분석(`pandas`)이나 웹 서버(`fastapi`) 같은 기능은 외부 패키지에 있다. 직접 만들지 않고 `import`나 `uv add`로 가져와 쓴다.
- **한 줄 쓰고 바로 결과를 본다.** (REPL)
  - `python`으로 REPL을 열면 코드를 한 줄씩 입력하면서 결과를 바로 확인할 수 있다. 파일을 따로 만들지 않고도 실험하며 배울 수 있다.
- **문법이 간결하고, 들여쓰기로 코드 블록을 구분한다.**
  - 중괄호 `{}` 대신 들여쓰기로 블록을 나눠서 코드 모양이 일정하고 읽기 쉽다. 대신 들여쓰기가 맞지 않으면 에러가 난다.
- **웹, 데이터 분석, 머신러닝 등 여러 분야에서 쓰인다.**
  - 하나의 언어로 웹 서버부터 데이터 분석, AI 개발까지 이어서 할 수 있어서 한 번 배우면 활용할 곳이 넓다.

### 보일러플레이트란

하려는 일과 상관없이 형식상 매번 써야 하는 코드이다.

파이썬은 파일 자체가 프로그램이다. 클래스도, Main도, 이름 공간도 없이 첫 줄부터 바로 본론을 쓴다.

비교 예시: 화면에 Hello 출력하기

```java
// Java
public class Main {
    public static void main(String[] args) {
        System.out.println("Hello");
    }
}
```

```py
# Python
print("Hello")
```

## 2. 파이썬은 어떻게 실행될까

### 번역이 필요하다

- 컴퓨터는 Python을 모른다. 누군가 컴퓨터가 이해하는 언어(기계어)로 번역해야 한다.
- 번역 방식은 두 가지이다.

| 구분 | 컴파일 방식 | 인터프리터 방식 |
| --- | --- | --- |
| 번역 시점 | 전체를 미리 번역한 뒤 실행 | 실행하면서 차례대로 번역 |
| 비유 | 책 전체를 번역해서 전달 | 동시통역 |
| 특징 | 실행 전에 번역 단계가 필요 | 바로 실행해볼 수 있음 |
| 예 | C 등 | Python |

- 파이썬은 보통 인터프리터 방식으로 분류한다. (제가 아는 바로는 CPython은 내부적으로 코드를 바이트코드로 바꾼 뒤 실행한다.)

### REPL: 인터프리터를 직접 써보기

- Read → Eval → Print → Loop: 입력을 읽고, 실행하고, 결과를 출력하는 것을 반복
- 터미널에서 `python`을 입력하면 열리는 `>>>` 화면
- 나가는 방법: `exit()`

## 3. 개발 환경 용어 정리

파이썬 프로젝트를 준비할 때 계속 나오는 세 가지 말이다. 다음 장의 uv를 이해하려면 먼저 알아야 한다.

- **패키지:** 남이 만들어 둔 라이브러리 묶음 (`fastapi`, `pandas` 등)
- **dependency(의존성):** 내 프로젝트가 동작하려면 필요한 패키지
- **가상환경:** 프로젝트마다 따로 쓰는 독립된 설치 공간 (`.venv`)

프로젝트마다 필요한 패키지와 버전이 다르다. 가상환경이 없으면 한 컴퓨터에 전부 섞여서 설치되고, 프로젝트끼리 버전이 충돌할 수 있다. 그래서 프로젝트마다 설치 공간을 나눈다.

## 4. uv로 파이썬 환경 만들기

### uv란

- 파이썬 패키지·프로젝트 관리 도구이다. Rust로 만들었고, Astral에서 2024년 2월에 공개했다.

**Q. 패키지, 버전, dependency, 가상환경을 uv가 다 해주나?**

네. 패키지 설치, 버전 기록과 고정(`uv.lock`), 가상환경 생성, 파이썬 버전 관리까지 uv 하나로 한다.

### 기존 방식과 비교: uv가 편리해진 점

기존에는 작업마다 다른 도구를 따로 써야 했다. uv는 이를 하나로 합쳐 놓았다. 표의 명령어는 5장에서 하나씩 실행한다.

| 작업 | 기존 방식 | uv |
| --- | --- | --- |
| 파이썬 버전 관리 | pyenv 같은 도구를 따로 설치 | `uv python install`, `uv python pin` 으로 해결. 필요한 버전이 없으면 자동으로 내려받음 |
| 프로젝트 시작 | 폴더, 가상환경, 파일을 직접 구성 | `uv init` 으로 파일 생성 |
| 가상환경 생성 | `python -m venv .venv` 직접 실행 | 필요할 때 `.venv`를 자동 생성 |
| 패키지 설치 + 기록 | `pip install`을 하고 목록은 직접 기록 | `uv add` 한 번으로 설치 + `pyproject.toml` 기록 + `uv.lock` 갱신 |
| 버전 고정 | `pip freeze > requirements.txt`를 직접 실행 | `uv.lock`이 자동으로 관리됨 |
| 환경 재현 | `pip install -r requirements.txt` | `uv sync` |
| 가상환경 사용 | 매번 활성화(`activate`) | `uv run`으로 활성화 없이 실행 |

- **도구가 하나로 합쳐졌다.** pip, venv, pyenv, pip-tools 등의 역할을 소개 자료들이 하나의 실행 파일로 합쳐졌다고 설명한다.
- **빠르다.** Rust로 만들어졌다. 출시 당시 Astral의 자체 벤치마크는 pip보다 캐시 없이 8~10배, 캐시가 있을 때 80~115배 빠르다고 밝혔다. (자체 측정이라 환경에 따라 다를 수 있다.)
- **기존 습관을 그대로 쓸 수 있다.** `uv pip install`처럼 pip와 비슷한 방식도 지원한다.
- **재현이 쉽다.** 락 파일로 팀원, 다른 컴퓨터, 서버가 같은 버전을 설치한다.

### 설치

```bash
winget search uv
winget install --id=astral-sh.uv -e
uv --version
```

- `winget install uv`처럼 이름만 써도 되지만, 비슷한 패키지와 헷갈릴 수 있다. ID(`astral-sh.uv`)와 `-e`(정확히 일치)로 지정하는 것이 안전하다.
- 설치 후 `uv --version`이 나오지 않으면 터미널을 새로 열어서 다시 확인한다.

## 5. 프로젝트 시작하기

### 명령어 세 개로 시작한다

```bash
uv init --no-package
uv python pin 3.12
uv add fastapi
```

### uv init --no-package: 프로젝트 만들기

- 빌드 시스템 없이 만드는 단순한 구조이다. 코드는 `src/` 폴더가 아니라 최상위의 `main.py`에 둔다.
- 만들어지는 파일: `.python-version`, `README.md`, `main.py`, `pyproject.toml` (그리고 `.git`, `.gitignore`)
- `.venv`와 `uv.lock`은 이후 `uv add`나 `uv run` 등을 실행할 때 생긴다.

### uv python pin 3.12: 파이썬 버전 정하기

- `.python-version` 파일에 `3.12`를 기록한다. 이 프로젝트가 쓸 파이썬 버전을 정하는 것이다.

### uv add fastapi: 라이브러리 설치하기

- `.venv`에 설치하고, `pyproject.toml`의 `dependencies`에 기록하고, `uv.lock`에 정확한 버전을 기록한다.
- FastAPI는 파이썬으로 API 서버를 만드는 라이브러리이다.

### pyproject.toml과 uv.lock은 왜 맞춰야 할까

- `pyproject.toml`: 내가 필요하다고 선언한 것 (라이브러리와 허용 버전 범위)
- `uv.lock`: 실제로 선택된 정확한 버전

둘이 어긋나면 "원하는 것"과 "설치되는 것"이 달라진다. 맞춰 두면 팀원, 다른 컴퓨터, 서버가 **같은 버전**으로 설치되어 버전 차이로 코드가 깨지는 일을 막는다. 두 파일을 맞추는 명령어가 `uv sync`이다.

```bash
uv sync
uv sync --locked
uv sync --frozen
```

- `uv sync`: 목록대로 `.venv`를 맞춘다. lock이 오래됐으면 다시 만든 뒤 설치한다.
- `uv sync --locked`: 두 파일이 어긋나 있으면 에러를 낸다.
- `uv sync --frozen`: lock 파일을 그대로 믿고 설치한다.
- 두 파일 모두 git에 커밋한다.
- `uv sync`는 `git clone` 직후나 `pyproject.toml`을 직접 수정한 뒤에 쓴다.

## 6. 코드 실행과 가상환경

### 가장 간편한 방법: uv run

- 활성화하지 않아도 `uv run`이 `.venv` 환경에서 대신 실행해 준다.

```bash
uv run main.py
uv run python
```

### 직접 활성화하는 방법 (Git Bash)

가상환경 안에서 계속 작업하고 싶을 때는 활성화한다.

```bash
source .venv/Scripts/activate
```

- 활성화되면 프롬프트 앞에 `(프로젝트이름)`이 붙는다.
- 끝낼 때는 비활성화한다.

```bash
deactivate
```

### source 명령어

- 파일 안의 명령어를 **지금 쓰고 있는 터미널에서 그대로 실행**하는 명령어이다.
- `source` 없이 실행하면 새로운 프로세스에서 실행되어 끝나면 변경도 사라진다. 활성화는 현재 터미널의 설정(`PATH` 등)을 바꿔야 해서 `source`를 쓴다.
- `activate`는 `.venv/Scripts/` 안에 있는 확장자 없는 파일(Bash용 스크립트)이다. 터미널 종류별로 파일이 따로 있다.

| 터미널 | 파일 |
| --- | --- |
| Git Bash | `activate` |
| 명령 프롬프트(cmd) | `activate.bat` |
| PowerShell | `Activate.ps1` |

### 활성화됐는지 확인하기

**Q. `which python`은 활성화된 가상환경 경로를 확인하는 건가?**

정확히는 `python`이라고 입력했을 때 **실행될 파이썬 파일의 경로**를 보여준다. 활성화되어 있으면 `.venv` 안의 python 경로가 나오고, 아니면 시스템에 설치된 python 경로가 나온다. 가상환경 폴더 경로 자체는 아래 명령어로 확인한다.

```bash
which python
echo $VIRTUAL_ENV
```

- `which python`: 실행될 python의 경로
- `echo $VIRTUAL_ENV`: 활성화된 가상환경 경로 (비활성화면 빈 줄)

## 7. 주피터 노트북

### 주피터(Jupyter)란

- 코드, 실행 결과, 설명 글(마크다운)을 **한 문서에 함께** 담아 실행하는 도구이다. 이 문서를 노트북이라고 부르고, 파일 확장자는 `.ipynb`이다.
- 노트북은 **셀(cell)** 단위로 구성된다.
  - 코드 셀: 파이썬 코드를 쓰고 실행하면 결과가 바로 아래에 나온다.
  - 마크다운 셀: 설명이나 메모를 글로 작성한다. (단축키 `M`으로 변환)
- 이름은 Julia, Python, R에서 따왔다고 알고 있는데, 이 부분은 확인하지 못했다.

### 왜 사용하나

- **실험하며 배우기 좋다.** REPL을 파일로 저장하고 편집할 수 있게 한 것과 비슷하다. 한 셀씩 실행해 결과를 확인하고, 틀리면 그 셀만 고친다.
- **코드, 결과, 설명이 한 문서에 남는다.** 표나 그래프 같은 결과까지 함께 저장되어 학습 기록이나 공유용 문서로 좋다.
- **앞 셀의 결과가 메모리에 남는다.** 앞 셀에서 만든 변수를 뒤 셀에서 쓸 수 있다. 데이터를 불러오는 것처럼 오래 걸리는 작업을 매번 다시 하지 않고 뒤쪽만 다시 실행할 수 있다.
- **데이터 분석, 머신러닝 실험에 많이 쓴다.**

### 주의할 점

- 셀을 실행하는 순서가 뒤섞이면 변수 값이 달라져 결과가 헷갈릴 수 있다. 이상하면 위에서부터 다시 실행해본다.
- 실제 서비스로 동작하는 코드는 보통 `.py` 파일로 작성한다. 노트북은 실험과 학습 쪽에 더 많이 쓴다.

### VS Code에서 사용하기

1. VS Code에 Jupyter 확장을 설치한다.
2. 프로젝트에 `ipykernel`을 설치한다.

```bash
uv add ipykernel
```

3. `.ipynb` 파일에서 Select Kernel → Python Environments → 내 프로젝트(`.venv`)를 선택한다.

- `ipykernel`은 노트북이 파이썬 코드를 실행할 때 쓰는 실행 엔진(커널)이다.

### 자주 쓰는 단축키

셀 바깥(명령 모드)에서 동작하는 단축키는 `Esc`로 명령 모드에 들어간 뒤 누른다. `Enter`는 편집 모드로 돌아간다.

| 단축키 | 동작 | 모드 |
| --- | --- | --- |
| `Esc` / `Enter` | 명령 모드 / 편집 모드 | - |
| `A` / `B` | 셀 위 / 아래에 추가 | 명령 |
| `M` | 마크다운 셀로 변경 | 명령 |
| `Y` | 코드 셀로 변경 | 명령 |
| `D` `D` | 셀 삭제 | 명령 |
| `Z` | 되돌리기 | 명령 |
| `L` | 줄 번호 켜기/끄기 | 명령 |
| `Alt + ↑` / `Alt + ↓` | 셀 이동 | 명령 |
| `Ctrl + Enter` | 셀 실행 | 공통 |
| `Shift + Enter` | 셀 실행 후 다음 셀로 이동 | 공통 |
| `Alt + Enter` | 셀 실행 후 아래에 새 셀 추가 | 공통 |

- `M`이 안 먹을 때: 편집 모드가 아닌지(`Esc`), 셀이 선택되어 있는지, 한영이 영문인지 확인한다.
- 셀 안에서는 `Ctrl + Enter`가 줄 삽입이 아니라 **셀 실행**이다.
